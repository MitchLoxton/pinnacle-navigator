## PROBLEMS

### Resolved this week

- **Page freeze / stability issue:** v0.18 required a dedicated stability hotfix.
- **Signup success looked like an error:** successful account creation was being displayed in the red auth-error treatment.
- **Create account UX was too cramped:** signup shared the sign-in presentation rather than having a proper dedicated flow.
- **Email verification returned toward localhost:** production signup code was not explicitly requesting the live YTIntel return URL. v0.28.1 now requests the production GitHub Pages URL.
- **Signed-in state could make the analyser feel restricted:** v0.28.1 explicitly restores core Analyse/Viral Lab controls during account bootstrap and auth-state changes.
- **Auth patch syntax failure:** CI caught an `Unexpected token 'catch'` before the bad build reached Pages; fixed before successful deployment.

### Still open / not yet fully verified

- **Fresh-account production verification round trip:** the app now requests the correct live URL, but the Supabase Auth redirect allow-list itself has not been independently verified through the available tooling. A brand-new signup must confirm the email and land back in the production app successfully.
- **End-to-end signed-out / signed-in analysis:** code is designed to keep the core analyser available regardless of account state, but this needs a clean browser test across signed-out, new signup, verified sign-in, refresh, sign-out and returning-session states.
- **Supabase security debt:** `public.ytintel_ai_setup` and `public.ytintel_ai_usage` were found with Row Level Security disabled. This must be fixed with deliberately designed policies; simply enabling RLS without policies could break the analyser backend.
- **Feature-layer complexity:** the rapid v0.18 → v0.28.1 progression created many layered scripts and overlapping UI behaviours. Shipping speed is now a reliability risk if the whole creator journey is not repeatedly tested as one product.
- **Real-user value evidence:** substantial functionality exists, but this weekly review does not yet have a verified completion-rate, retention, creator-output or paid-conversion dataset proving which parts generate the most user value.

## LESSONS

1. **Validation gates are worth keeping.** The auth syntax bug was caught before production because the release workflow explicitly checked the new file.
2. **Release truth should follow deployment truth.** Discord notifications now belong after the live deployment, not merely after editing release notes.
3. **Auth is a front door, not a side feature.** A broken account state made the whole product feel broken even though the core analyser itself was not supposed to require login.
4. **A complete workflow matters more than another feature.** Viral Forensics, Style Banks, Idea Lab, Production Studio and Creator Loop only become valuable as a system if a creator can move through all of them without confusion or dead ends.
5. **Weekly operating evidence beats memory.** Future Sunday reviews should compare the prior week's Top 3 against what actually shipped, instead of reconstructing priorities retrospectively.
