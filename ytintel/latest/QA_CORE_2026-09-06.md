### P0 fixed: signed-out Analyse was incorrectly authentication-gated

Root cause: the old public base chain had become `v09 -> v08 -> v07 -> ytintel-intel`, but `ytintel-intel` had been repurposed for authenticated cloud monitoring. Signed-out core Analyse therefore returned `Sign in required`.

Fix: `ytintel-v07` was restored as a self-contained public analysis base (`0.7.4-core-restored`) and no longer calls the authenticated cloud-monitoring worker. `v09` remains the production entry point.

### P1 fixed: transcript edge cases

`ytintel-v08` `0.8.2` now:

- anchors opening/hook evidence to the first available caption timestamp;
- collapses adjacent repeated rolling-caption blocks of three or more words;
- preserves source timestamps and records how many segments were cleaned;
- keeps retention/attention labels explicitly framed as transcript/replay proxies rather than private Studio metrics.

## Auth architecture static verification

`v201-always-on.js` loads `v291-auth-core.js` first and awaits `YTIntelAuthReady` before account/cloud/commercial layers are loaded. The canonical auth core patches the Supabase factory so matching YTIntel project clients reuse one persisted session/client.

A further reliability hotfix on 2026-09-06 changed late-layer loading from concurrent fire-and-forget injection to deterministic sequential loading after canonical auth is ready. This removes a remaining race between account, cloud, product-fix, Packaging and commercial layers.

Real signed-in and signed-out browser screenshots/recording are still required before the auth checkpoint can be closed.

## Deep Packaging blocker — not hidden

A real deep Packaging production request reached `ytintel-v082` and returned HTTP 503 with `generic_fallback=false`, correctly refusing generic filler.

A provider diagnostic then reached the configured OpenAI project successfully but returned HTTP 429 with `insufficient_quota / credit_balance_exhausted`.

This establishes:

- the provider key exists;
- the key reaches the OpenAI API;
- the failure is not an invalid-key or model-name bug;
- the current blocker is exhausted OpenAI API credits.

Deep Packaging must not be marked complete until credits are restored and at least three production outputs are verified against their source transcript/examples/replay evidence.
